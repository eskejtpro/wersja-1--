6. JAK DZIAŁA SERWER (KRÓTKO)

   a) BINDING I BEZPIECZEŃSTWO
      - Domyślnie słucha tylko na 127.0.0.1:3000 (localhost)
      - Dostępny WYŁĄCZNIE z tego samego komputera
      - TLS opcjonalny (do LAN wymaga certyfikatu)
      - Wysyła kontrolowany błąd przy LAN bez TLS
      - Nie wysyła żadnych danych poza komputer

   b) AUTENTYKACJA
      - Single-user (jedna konto: "local")
      - Hasło haszowane scrypt (secure KDF)
      - Login zwraca token Bearer z TTL 8h
      - Brute-force limitowany (5 prób / 15 min)
      - Logout unieważnia sesję

   c) ENDPOINTY
      Publiczne (bez auth):
      - GET /api/health          — status & wersja serwera
      - GET /api/version         — info o aplikacji
      - POST /api/auth/login     — logowanie → token

      Wymaga sesji (nagłówek: Authorization: Bearer <token>):
      - GET /api/data            — pobierz dane
      - POST /api/data           — zapisz dane atomowo
      - GET /api/sync/status     — revision + hash
      - POST /api/auth/logout    — wylogowanie
      - POST /api/agent/analyze  — lokalna analiza

      Aktualizacje (bez auth; zwracają "unavailable" bez manifestu):
      - GET /api/update/check
      - GET /api/update/history
      - GET /api/update/download/:version
      - POST /api/update/apply (wyłączone)
      - POST /api/update/rollback (wyłączone)

   d) MAGAZYN DANYCH
      - Ścieżka: A:\GymTracker-server-ready\server_data.json
      - Tworzony dopiero przy pierwszym POST /api/data
      - Zapisy atomowe (temp file → rename)
      - Przechowuje: schemaVersion, revision, updatedAt, contentHash, data
      - Po restarcie proces czyta i przywraca stan

   e) AGENT LOKALNY

      - Nie wysyła danych na zewnątrz

8. PRZYKŁAD: LOGOWANIE I ZAPIS DANYCH (curl)

   1. Zaloguj się:
   curl -X POST http://127.0.0.1:3000/api/auth/login \
     -H "Content-Type: application/json" \
     -d '{"username":"local","password":"test123"}'
   -> {"token":"eyJhb...", "expiresAt":"2026-09-19T03:34:00Z"}

   2. Pobierz dane:
   curl -H "Authorization: Bearer eyJhb..." \
     http://127.0.0.1:3000/api/data
   -> {"schemaVersion":"2.24","revision":1,"updatedAt":"...", "data":{...}}

   3. Zapisz dane (ze sprawdzeniem rewizji):
   curl -X POST http://127.0.0.1:3000/api/data \
     -H "Authorization: Bearer eyJhb..." \
     -H "Content-Type: application/json" \
     -d '{"schemaVersion":"2.24","revision":1,"contentHash":"abc123","data":{...}}'
   -> Jeśli revision pasuje: {"success":true}
   -> Jeśli konflikt: {"error":"conflict","current":2} (409)

   4. Sprawdzenie statusu:
   curl -H "Authorization: Bearer eyJhb..." \
     http://127.0.0.1:3000/api/sync/status
   -> {"revision":1,"updatedAt":"...","contentHash":"abc123","deviceId":"local-server","online":true}
